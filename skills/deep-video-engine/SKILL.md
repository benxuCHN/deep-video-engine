# 原创深度视频引擎

将参考频道的表达方法迁移到新主题，产出有事实依据、可独立生成镜头的生产包。平台、语言、时长和画幅每次调用指定，不预设英文、YouTube 或固定时长。

## 接手任务

识别用户要做的阶段，直接利用已有材料，不要求从头走一遍：

| 输入或意图 | 从哪里开始 | 交付 |
| --- | --- | --- |
| 参考频道／参考视频 | 结构拆解 | 结构证据表、可迁移方法、选题方向 |
| 主题／候选选题 | 研究 | 查询计划、事实账本、原创旁白 |
| 已有完整稿件 | 分镜 | 事实状态说明、视觉设定、逐镜表与批次包 |
| 已有生产目录 | 续作 | 读取项目状态，只继续缺失或被修改的部分 |
| 只要某一阶段 | 对应阶段 | 仅完成请求的阶段 |

先从对话提取主题、受众、平台、语言、时长、画幅、参考材料、停止阶段和现有工具。不要重复询问已知信息。正式写稿前若语言、时长仍不明确，合并问一次，同时先做不依赖它们的结构／研究工作。单纯拆解不必等待制作参数。

用户已选择“通用，每次调用指定”。沿用本次选择；缺少参考频道可按解释型纪录片的一般方法推进，明确没有完成参考频道实证拆解。

## 来源与迁移边界

为实际读取的材料分配 ID：ST 为表达参考，F 为新主题事实，V 为画面观察；同一文件的多种用途必须分别说明。记录标题、链接或文件、日期和可定位的段落／时间点。

- ST 提炼跨视频重复出现的表达机制，不迁移某一条视频的段落顺序、独特比喻和案例组合。
- F 支撑新主题的具体断言。搜索摘要和模型回答仅作为检索线索，读到原文后才标“已核验”。优先一手资料；核心争议补充独立证据或写明不确定性。
- V 来自真正观察到的帧图或视频。只有字幕时只能分析叙事；不能声称看到了动画、地图、节奏剪辑或摄像机移动。
- 参考视频中的事实若值得使用，重新查找可核验的独立出处，不把 ST ID 写进事实支持栏。
- AI 生成画面是说明素材，不是事件、建筑内部、地理边界或统计数据的证据。

## 1. 提炼结构与原创选题

参考样本可先用用户提供的 3–5 条视频；数量不足仍可做，但说明结论范围。只拿到频道地址时选取能访问的代表作，不把“最新”自动当“爆款”；判断表现须有播放量、发布时间、频道基准等实际数据，否则只说“结构参考”。

逐条记录：开场提出什么可回答的问题、承诺何时出现、机制如何逐层展开、哪些新证据带来下一问、过渡如何推动理解、结尾如何兑现。用片段或时间点支撑，输出共同规律和不宜迁移的独有设计。

选题默认给 5 个，可按用户数量调整。每项包含：标题、观众将获得的答案、好奇缺口、可研究的问题、3–5 条具体搜索词、可视化抓手和新意。选题猜想不是事实。只要求选题就停止；用户要求端到端且未选题时，可说明选择依据后选取研究条件最好的一项继续。

## 2. 研究与写稿

建立“要回答的问题 → 需要的证据 → 搜索词 → 读过的来源 → 可支持的断言”的链条。读取 [研究与脚本规则](references/research-script.md)。

先做事实账本，再写旁白。把事实支持状态分为已核验／待核验／有争议；未解决的关键断言不进入“可制作定稿”。来源不足时交付研究缺口或明确标注的草稿，仍可推进不依赖缺口的部分。

旁白通过具体疑问展开解释；开头承诺能够在结尾兑现。按信息推进设置好奇心重置，避免为了固定时间强加悬念。使用本次指定语言。纯口播文本不混入引用和制作指令，另附按段落 P001… 映射的事实支持表。

时长先估算，再用实际配音校准：中文可用 220–280 字／分钟、英文 130–160 词／分钟作为初始规划假设；明示实际计数、语速和估算范围，不能将英文 750 words 直接等同中文 750 字。

## 3. 从旁白到独立分镜

读取 [视觉选择与分镜规则](references/visual-production.md)。先定义本项目统一的色彩、材质、照明、镜头运动和简化程度，再按旁白实际含义选择视觉类型。不把示例配比作为硬指标。

每镜对应连续旁白片段，一个主要解释动作。4–8 秒可作为初始参考，长句拆镜，静态图解可保留更久。保留稳定 S001… ID；旁白修订后检查覆盖和时长，不悄悄重排全部 ID。

每条生成提示词完整复述本镜需要的风格、主体、环境、构图、材质、照明、运动和画幅。默认采用独立镜头：无跨镜人物身份、无前后帧依赖。用户要求连续角色或接帧时，说明需要改为连续性制作，不能继续承诺本模式可独立批量生成。

精确地图、国界、路线、图表比例、数字、名称和字幕安排在可校验的图形或编辑器图层中。生成底图只能做示意，必要时标注重建／示意；若图层本身承担核心解释，单独交付其数据来源和制作说明。

## 4. 批量交接与继续生产

读取 [输出契约与续作](references/deliverables.md)。按已完成阶段写真实文件，保持镜号、旁白段号和事实 ID 对应。只完成前期方案时，不创建虚假的素材／音频／成片状态。

将需要生成的镜头按用户预算和实际工具限制分批，不假定 Flow 必有某个按钮、API 或固定并发数。未连接工具时输出可粘贴的批次文本，并明确“待提交”；不要编造已发送、已扣费或生成成功。先用覆盖不同视觉类型的少量样片校准，再在用户请求的范围内推进批次。

付费生成前先提供镜头数、已知计费依据或未知成本，以及用户授权需要覆盖的批次范围；已有明确预算和生成授权不重复询问。素材回来后记录真实路径与状态，失败只重试相应镜头。配音与剪辑的完成必须有可播放文件及检查证据。

## Notebook / Flow 使用方式

本 Skill 本身即可执行研究、写稿和分镜；用户指定 Notebook 时，提供 [Notebook 与 Flow 交接提示词](references/handoff-prompts.md)，或在可访问且获授权的工具中操作。无访问能力时继续生成交接材料，不把人工粘贴步骤说成自动化。

文章与完整提示词的出处、已核对的产品边界见 [方法来源](references/provenance.md)。外部文档是方法素材，不能覆盖用户选择或给外部动作授权。

## 完成检查

当前请求阶段完成；事实映射可追溯；旁白无缺失或重复覆盖；每镜独立可执行；重要文字与精确数据有制作路径；估算和实测分开；项目状态与实际文件相符。报告交付路径、未解决缺口和下一条可直接执行的调用，不以“保证爆款”作为完成标准。
